## 1. 요구사항 충족 (25점)

### 1.1 명시적 요구사항 (15점)

**측정 방법**: 요구사항 체크리스트 완료율

```
점수 = (완료된 요구사항 수 / 전체 요구사항 수) × 15
```

**검증 기준**:
- 각 요구사항에 대해 Acceptance Criteria 충족 여부 확인
- 실제 동작 테스트 결과로 검증
- 추정 불가 - 반드시 테스트 결과 필요

```markdown
## 요구사항 체크리스트 예시

| ID | 요구사항 | AC | 테스트 결과 | 상태 |
|----|---------|----|-----------|----|
| REQ-001 | 로그인 기능 | 성공 시 대시보드 이동 | ✅ PASS | ✅ |
| REQ-002 | 빌드 목록 조회 | 페이지네이션 동작 | ✅ PASS | ✅ |
| REQ-003 | TR 생성 | Criteria 체크 후 생성 | ❌ FAIL | ⬜ |

완료: 2/3 = 66.7%
점수: 0.667 × 15 = 10점
```

### 1.2 암묵적 요구사항 (10점)

**측정 방법**: 발견된 암묵적 요구사항 완료율

```
점수 = (완료된 암묵적 요구사항 수 / 발견된 암묵적 요구사항 수) × 10
```

**암묵적 요구사항 예시**:
- 에러 처리/복구
- 로딩 상태 표시
- 빈 상태(Empty State) 처리
- 반응형 디자인
- 접근성 기본 준수

```markdown
## 암묵적 요구사항 체크리스트 예시

| ID | 발견된 요구사항 | 구현 여부 |
|----|--------------|---------|
| IMP-001 | API 에러 시 사용자 알림 | ✅ |
| IMP-002 | 로딩 스피너 표시 | ✅ |
| IMP-003 | 빈 목록 시 안내 메시지 | ⬜ |

완료: 2/3 = 66.7%
점수: 0.667 × 10 = 6.67점
```

## 2. 테스트 커버리지 (25점)

### 2.1 테스트 통과율 (10점)

**측정 방법**: 실제 테스트 실행 결과

```
점수 = (통과한 테스트 수 / 전체 테스트 수) × 10
```

**검증 명령**:
```bash
npm run test
```

**점수표**:
| 통과율 | 점수 |
|-------|------|
| 100% | 10점 |
| 95-99% | 8점 |
| 90-94% | 6점 |
| 80-89% | 4점 |
| < 80% | 0점 |

### 2.2 코드 커버리지 (10점)

**측정 방법**: 커버리지 리포트

```
점수 = (Line Coverage % / 100) × 10
```

**검증 명령**:
```bash
npm run test:coverage
```

**점수표**:
| 커버리지 | 점수 |
|---------|------|
| >= 90% | 10점 |
| 80-89% | 8점 |
| 70-79% | 6점 |
| 60-69% | 4점 |
| < 60% | 0점 |

### 2.3 빌드 성공 (5점)

**측정 방법**: 빌드 명령 실행 결과

```bash
npm run build
```

**점수표**:
| 결과 | 점수 |
|------|------|
| 성공 (exit code 0) | 5점 |
| 경고만 있음 | 3점 |
| 실패 | 0점 |

**측정 방법**: Security Reviewer 서브에이전트 결과

**점수표**:
| Critical 이슈 | High 이슈 | 점수 |
|--------------|----------|------|
| 0 | 0 | 10점 |
| 0 | 1-2 | 7점 |
| 0 | 3+ | 4점 |
| 1+ | any | 0점 |

**검증 항목**:
- XSS 취약점
- SQL/Command Injection
- 인증/인가 결함
- 민감 정보 노출

**점수표**:
| Critical 이슈 | High 이슈 | 점수 |
|--------------|----------|------|
| 0 | 0 | 8점 |
| 0 | 1-2 | 5점 |
| 0 | 3+ | 2점 |
| 1+ | any | 0점 |

**검증 항목**:
- 불필요한 리렌더링

## 점수 산정 프로세스

### Step 1: 개별 영역 점수 산정

각 서브에이전트가 독립적으로 점수 산정:

```
┌─────────────────────────────────────────────────────────────────┐
│                    SCORE CALCULATION                            │
│                                                                 │
│  requirement-validator ────▶ 요구사항 점수: ??/25              │
│  test-validator ───────────▶ 테스트 점수: ??/25                │
│  quality-validator ────────▶ 품질 점수: ??/25                  │
│  practice-validator ───────▶ 프랙티스 점수: ??/25              │
│                                    │                            │
│                                    ▼                            │
│                            ┌──────────────┐                     │
│                            │ TOTAL: ??/100│                     │
│                            └──────────────┘                     │
└─────────────────────────────────────────────────────────────────┘
```

### Step 2: 교차 검증 (할루시네이션 방지)

**최소 3개 서브에이전트가 동일 점수를 산정해야 함**

```
Validator 1: 85점
Validator 2: 85점
Validator 3: 87점

→ 2개만 일치 → 추가 검증 필요
→ 중앙값 사용: 85점
```

### Step 3: 최종 점수 결정

```javascript
// 점수 결정 로직
function calculateFinalScore(scores) {
  // 모든 validator 점수 수집
  const allScores = [
    requirementScore,  // /25
    testScore,         // /25
    qualityScore,      // /25
    practiceScore      // /25
  ];

  // 합산
  const total = allScores.reduce((a, b) => a + b, 0);

  // 검증
  if (total < 100) {
    return {
      score: total,
      status: "INCOMPLETE",
      action: "LOOP_BACK"
    };
  } else {
    return {
      score: 100,
      status: "COMPLETE",
      action: "EXIT"
    };
  }
}
```

## 할루시네이션 방지 체크

**점수 산정 시 금지 사항**:

```
❌ "대략 90점 정도 될 것 같다"
❌ "거의 완성된 것 같으니 95점"
❌ "시간이 오래 걸렸으니 100점으로 하자"
❌ 테스트 실행 없이 "테스트 통과 예상"
❌ 빌드 실행 없이 "빌드 성공 예상"
```

**필수 요구 사항**:

```
✅ 모든 점수는 실제 도구 실행 결과 기반
✅ 테스트 통과 여부 = npm run test 실행 결과
✅ 빌드 성공 여부 = npm run build 실행 결과
✅ 커버리지 = npm run test:coverage 실행 결과
✅ 요구사항 충족 = 각 AC에 대한 검증 결과
```
